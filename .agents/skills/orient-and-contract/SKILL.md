# Orient And Contract

1. Inspect real files, revision, issues/PRs and configured workflows; distinguish implemented, proposed and unknown facts.
2. Write a short acceptance contract with scope, non-goals, constraints, evidence and integration owner.
3. Map dependencies and conflicts before parallel work; keep small changes direct.
4. Proceed based on observed context; flag unresolved decisions.

**Evidence:** report only actual actions and observable results. Do not override higher-priority host permissions or project requirements.
